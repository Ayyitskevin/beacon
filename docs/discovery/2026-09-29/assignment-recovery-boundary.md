## Destination and non-duplication

AC22 asks whether the promised at-most-one automatic Assignment Recovery Attempt can be evidenced separately from existing Run recovery. Workspace sources `reports/beacon-m0-inventory-20260912/INVENTORY.md:71` and `reports/beacon-path-to-complete-20260912/ROADMAP.md:120–121` place this gap in M6/M7. Its Team/Mission actor map is reused, not redrafted or transferred as proof at this different base.

The new finding is that **Run terminality, failure evidence, Assignment attempt lineage and reassignment are different boundaries**. Neither counting Runs nor accepting an unresolved Run establishes the Assignment recovery allowance. Existing code supplies reusable terminal evidence; the Assignment-to-attempt and Handoff/Attention interfaces were not located in the bounded search below.

## Accepted meanings, unchanged

[ADR0010:7–15](../../adr/0010-one-recovery-then-handoff.md#L7) requires one automatic attempt for eligible failed work under unchanged authority, bindings, Assignment and remaining budget; second failure pauses that Assignment and leads to durable Handoff or Attention when safe reassignment is impossible. [BLUEPRINT:369–373](../../BLUEPRINT.md#L369) additionally states the same Proposal and a distinct recorded attempt. An Assignment is accountable Agent/work association, not a lease; Handoff retains context, Artifacts, verification, risks and authorship; Recovery Attempt is not simply restart ([CONTEXT:147–164](../../../CONTEXT.md#L147)). Attention needs an unresolved condition, eligible named actor and concrete action; ordinary status is not automatically Attention ([BLUEPRINT:345–359](../../BLUEPRINT.md#L345)). No eligibility classifier or policy choice is introduced here.

## Existing state, feedback, coupling and order

**State owners.** `DeclaredCheckService::execute` opens an execution Run, then obtains a separate pinned preflight receipt; it does not create an Assignment attempt. Its opener persists Workspace/Project and revision bindings; its closer commits Run state, Receipt and `run.executed` event together ([declared_checks.rs:172–194](../../../crates/beacond/src/declared_checks.rs#L172), [250–349](../../../crates/beacond/src/declared_checks.rs#L250)). This already makes “number of Runs” an unsafe substitute for “number of Assignment recovery attempts”: even one check execution has its own preflight boundary.

**Startup ordering.** Supervisor reconciliation completes interrupted dispatch evidence first, then reconciles expired Run leases, commits, and only then starts query-only verification ([lib.rs:1903–1920](../../../crates/beacond/src/lib.rs#L1903)). Lease reconciliation validates identities before changing expired open Runs to `unconfirmed`; it does not schedule work ([check_preflight.rs:795–828](../../../crates/beacond/src/check_preflight.rs#L795)). Dispatch reconstruction reads surviving preparation and landing evidence, preserves the existing Run identity, and calls the same terminal writer ([dispatch.rs:2539–2644](../../../crates/beacond/src/dispatch.rs#L2539)). The writer couples terminal state, Receipt and event; it relies on its caller's transaction ([1930–1975](../../../crates/beacond/src/dispatch.rs#L1930)). Replacing reconstruction with a retry would change the operation, not merely finish its evidence.

**Feedback does not collapse uncertainty.** Reconstruction includes `reconstructed_after_interruption` and specific unknowns ([dispatch.rs:2647–2694](../../../crates/beacond/src/dispatch.rs#L2647)). A terminal `LandingUnobserved` receipt maps to Run state `refused`, whereas `unconfirmed` means lease expiry without a terminal receipt ([283–290](../../../crates/beacond/src/dispatch.rs#L283)); neither establishes eligibility to repeat effects. Likewise, execution `Completed`/`verified` means terminal evidence exists, not that checks or Mission succeeded ([ADR0031:41–54](../../adr/0031-execution-receipt-v2.md#L41)). A source test explicitly expects a failing check's exit 7 alongside `Completed` ([tests/declared_checks.rs:757–786](../../../crates/beacond/tests/declared_checks.rs#L757)).

**Readers and operational coupling.** Local `RecentReceipts` calls the authenticated bounded query ([local_transport.rs:2216–2220](../../../crates/beacond/src/local_transport.rs#L2216)). Its own comments exclude using that window as the exhaustive Resume review set ([recent_receipts.rs:85–102](../../../crates/beacond/src/recent_receipts.rs#L85)). At this base, receipt classification accepts only preflight and declared-check kinds, refusing other kinds ([311–348](../../../crates/beacond/src/recent_receipts.rs#L311)); the later W03 map's dispatch-reader description is not portable evidence for this base. Backend `PauseService` instead reads all open/unconfirmed Run IDs, refuses ordinary Resume while they remain, and records an explicit acceptance reason and IDs atomically with Resume ([dispatch.rs:3283–3353](../../../crates/beacond/src/dispatch.rs#L3283), [3456–3469](../../../crates/beacond/src/dispatch.rs#L3456)). Installation Pause/Resume is not Assignment pause or reassignment. Its documented missing interruption/Worker/UI surfaces remain missing claims, not completed integration ([3235–3237](../../../crates/beacond/src/dispatch.rs#L3235)).
